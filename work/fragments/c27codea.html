用 FastMCP 写一个 MCP ServerDECLARATIVE TOOLS · AUTO SCHEMA · AUTO TRANSPORT

书 22.7.1 的完整记笔记 server:装饰器声明 tool 与 resource,Schema 与传输全自动——这就是「N×M 集成问题」的标准答案长什么样。

from pathlib import Path
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("notes-server")          ① 一个实例=一个 server
NOTES_DIR = Path.home() / ".notes"

@mcp.tool()                               ② 声明式 tool
def create_note(title: str, content: str,
                tags: list[str] | None = None) -> str:
    """Create a new text note. Use this when
    the user wants to save information."""  ③ docstring 给 LLM 看
    safe = "".join(c if c.isalnum() or c in "-_" else "_"
                   for c in title).strip()  ④ 输入校验:防路径穿越
    p = NOTES_DIR / f"{safe}.md"
    p.write_text(f"---\ntitle: {title}\n---\n\n" + content,
                 encoding="utf-8")
    return f"Note saved to {p}"
@mcp.resource("notes://{title}")        ⑤ URI 路由的只读数据
def get_note(title: str) -> str:
    return (NOTES_DIR / f"{title}.md").read_text("utf-8")

if __name__ == "__main__":
    mcp.run()  ⑥ stdio / Streamable HTTP 自动选择
①②声明式,免手写 Schema
@mcp.tool() 从 Python 类型注解 + docstring 自动推断 JSON Schema——相比低层 API 省掉整个 inputSchema 手写环节。
③docstring 是 prompt 的一部分
模型靠它决定「何时调用」。写清「何时用」比写清「怎么做」更重要——这是工具描述工程的最小单元。
④⑤校验在 server,数据与动作分离
路径穿越是 tool 的头号注入面,文件名清洗是底线;resource 是只读「数据」,tool 是带副作用的「动作」。
⑥传输对上层透明
本地子进程走 stdio,远程走 Streamable HTTP——同一份代码两种部署,Client 不需要改动。
运行pip install "mcp[cli]" · 启动:mcp run notes_server.py(stdio)或 --transport streamable-http;预期:server 就绪等待 Client 握手。
