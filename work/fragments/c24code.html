生产级循环的伪代码THE CANONICAL AGENT LOOP

书 19.3-19.4:五个原语(自动化·工作树·技能·连接器·子 Agent)外加外部状态持久化,装配成一段恒温器式的规范循环——推理、行动、回填、终止判定。

def agent_loop(goal: str, max_steps: int = 50,
               budget: TokenBudget = None):
    """The canonical agent loop structure."""
    state = initialize_state(goal)     ① 加载外部状态和目标
    for step in range(max_steps):
        thought = model.reason(state)  ② 推理(ReAct 风格)
        action = model.choose_action(state)
        observation = environment.execute(action)
        state = update_state(state, thought, action, observation)
        if state.token_count > CONTEXT_BUDGET * 0.8:
            state = compact(state)      汇总旧步骤
        if verifier.passes(state, goal): ③ 确定性检查
            persist_state(state, status="success")
            return Success(state)
        if no_progress_detected(state, window=3):  ④ 无进展
            persist_state(state, status="stuck")
            return escalate_to_human(state)
        if budget and budget.exhausted():
            persist_state(state, status="budget_exceeded")
            return escalate_to_human(state)
    persist_state(state, status="max_steps")   ⑤ 硬性上限
    return escalate_to_human(state)
①外部状态为何放循环外
LLM 在两次调用间是无状态的,循环连续性必须驻留磁盘——Markdown 进度文件、数据库或 git 日志;开局加载、每个出口回写,即进度·失败记忆·审计轨迹。
②一次迭代的执行流
推理→选动作→环境执行→回填状态(ReAct 风格);token 超预算 80% 即 compact 汇总旧步骤——丢弃噪声的同时保留相关历史,这就是上下文管理。
③验证器是循环的灵魂
verifier.passes 是确定性检查:循环的可靠程度不会超过它最不可靠的那一步验证;绝不让生成模型评判自己的输出——制造者与检查者必须分离。
④⑤终止条件:上限与无进展
success / stuck(3 步无进展)/ budget_exceeded / max_steps=50 硬上限;每个出口都先 persist_state 再 escalate_to_human——状态文件即审计轨迹。
运行此为 §19.4 结构模板;最小可运行实例是 19.5.1 验证循环:for attempt in range(MAX_ATTEMPTS) 内 run_tests(),失败即带失败日志重试;预期:测试转绿退出,或重试预算耗尽升级人类。
