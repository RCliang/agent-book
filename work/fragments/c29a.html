单一通才 Agent 无法兼顾知识广度与能力深度。Google 于 2025 年 4 月发布的开放协议 A2A,让异构 Agent 相互发现、委派与协作——不透明执行:不探查对方内部,只共享能力与任务。

01为何 Agent 要通信
通才 Agent 难兼顾广度与深度。上下文有限、领域专业化(CodeAgent·LegalAgent)、并行扇出、故障隔离、任务交接——各献所长,短板委派。
02五条设计原则
不透明执行:只经声明接口交互,不探查内部;企业就绪:OAuth 2.0·JWT·审计内建;模态无关;复用 HTTP+JSON-RPC 2.0+SSE;异步优先。
03Agent Card 与消息
能力名片:.well-known/agent.json 上的 JSON 清单,声明能力·认证·端点·skills 示例,支撑能力路由;消息=role+parts(text·file·data)。
图:A2A 客户—远程 Agent 交互——先经 Agent Card 发现能力,再 send_task 委派,SSE 流式回传或 webhook 推送;任务沿七态状态机推进(rejected 为 v1.0 新增)
认证与授权按请求执行:Bearer(JWT/OAuth 2.0)、API 密钥、mTLS、OpenID Connect;还须校验授权 scope,否则多 Agent 系统会出现权限提升漏洞。
