Client 四阶段与 Host 连接池INITIALIZE · DISCOVER · CALL · ROUTE

左侧:最小 Client 的握手—发现—调用四阶段;讲解卡:书中 22.7.3 的 MCPHost 连接池——多 server 时工具如何统一路由。

import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    params = StdioServerParameters(          ① 如何拉起 server 子进程
        command="python", args=["notes_server.py"], env=None)
    async with stdio_client(params) as (read, write):
      async with ClientSession(read, write) as session:
        await session.initialize()            ② 能力协商握手

        tools = await session.list_tools()    ③ 工具发现
        for t in tools.tools:
            print(f" - {t.name}: {t.description[:60]}")

        result = await session.call_tool(      ④ 执行(先经用户同意)
            "create_note",
            arguments={"title": "MCP Architecture Notes",
                       "content": "MCP uses JSON-RPC 2.0.",
                       "tags": ["mcp"]})
        print(f"Tool result: {result.content[0].text}")

asyncio.run(main())
①②stdio 拉起 + 能力协商
Client 以子进程方式启动 server,经 stdin/stdout 通信;initialize() 交换 protocolVersion 与 capabilities,之后全是 JSON-RPC 2.0。
③发现即集成
server 动态注册的 tool 无需改 Client 代码——N 个应用×M 个工具的集成问题由此降为 N+M。
④同意门控在 Host
带副作用的调用前,Host 须展示该 tool 将做什么、区分只读/破坏性并留审计日志;被攻破的 server 可借 resource 注入 prompt。
+多 server:MCPHost 连接池(22.7.3)
书中给出 Host 池:tool_registry[tool.name]=(server, tool) 把工具名路由到正确会话——LLM 只见统一工具面。
