MCP:架构与原语HOST · CLIENT · SERVER · FOUR PRIMITIVES

每个新框架都在重写工具连接器。MCP(Anthropic 2024)以 JSON-RPC 2.0 统一接口,把 N×M 集成压成 N+M——如 USB 之于设备。

N+M20 框架×50 工具:1000→70(−14×)
4原语 Tools·Resources·Prompts·Sampling
2传输 stdio·Streamable HTTP
3角色 Host·Client·Server
01工具集成问题
每个框架×每个工具都要定制连接器,负担平方级增长;MCP 让各方只实现一次协议——类比 USB·HTTP·LSP。
02三角色模型
Host 管体验与安全策略,内含一或多个 Client;Client 与单个 Server 一对一有状态会话;Server 是既有 API 的薄包装。
03生命周期与传输
四阶段:initialize→能力协商→运行→关闭;传输 stdio(本地子进程)或 Streamable HTTP(可升级 SSE 流)。
图 22.2 · MCP 架构:Host 内多个 Client 与多个 Server 保持有状态会话;Server 包装外部服务,经 stdio 或 Streamable HTTP 传输
Sampling 反转唯一方向相反的原语:Server 请求 Host 执行一次 LLM 推理,Host 保留完全控制权——server 无需自备模型。
