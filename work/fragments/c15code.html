SFT 两开关:打包与掩码PACKING · COMPLETION-ONLY LOSS

书第 10 章两件套:packing 收回浪费在 padding 上的 50-80% 算力,completion-only mask 把 gradient 聚焦到 assistant 回应——一个管效率,一个管信号。

from trl import SFTConfig, SFTTrainer, DataCollatorForCompletionOnlyLM
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

def formatting_func(example):                    ① chat 模板拼接对话
    messages = [
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": example["instruction"]},
        {"role": "assistant", "content": example["response"]}]
    return tokenizer.apply_chat_template(messages, tokenize=False)

response_template = "<|start_header_id|>assistant <|end_header_id|>"
collator = DataCollatorForCompletionOnlyLM(      ② 此 token 后才开始算 Loss
    response_template=response_template, tokenizer=tokenizer)

config = SFTConfig(
    max_seq_length=4096,
    packing=True,                                ③ 启用序列打包
    per_device_train_batch_size=4, learning_rate=2e-5)
trainer = SFTTrainer(model=model, args=config, train_dataset=dataset,
    data_collator=collator,                      ④ 仅对 completion 计算 Loss
    formatting_func=formatting_func)
trainer.train()
①模板先于训练
模型在模板化后的 token 流上学习:模板定义对话角色边界——模板错了,训练数据就错了。
②模板串是分界线
collator 在序列中精确匹配 response 模板串,其后的 assistant token 才计入 loss。
③把 padding 的钱赚回来
长短混合时 50-80% 计算浪费在 padding;packing 以 EOS 分隔拼满 4096,填充率 85-95%。
④为何 mask prompt
prompt 段 loss 置 -100:教模型回应而非背题;极短回答场景需保留部分 prompt 信号。
运行TRL SFTTrainer:packing=True + response_template 自动掩码;预期训练 loss 平稳下降。
