最小的自定义 LLM Agent 环境GYMNASIUM · RESET/STEP 契约

书 21.8 的 FileEditEnv:Agent 面对一个含 bug 的文件与失败的测试,不断编辑直到通过;观察与动作均为纯字符串,奖励来自真实运行测试而非 LLM 裁判。

@dataclass
class StepResult:
    observation: str    输入给 LLM 的文本
    reward: float       0.0 或 1.0
    terminated: bool    任务解决或达最大步数
    truncated: bool     预算超出被截断
class FileEditEnv:   动作: view | edit | run_tests | submit
    def reset(self, seed: int | None = None):  ① 新回合
        self._workdir = Path(tempfile.mkdtemp(prefix="fileenv_"))
        (self._workdir / "solution.py").write_text(self.buggy_code)
        self._step_count = 0
        return self._build_observation(...), {"step": 0}
    def step(self, action: str) -> StepResult: ② 一步交互
        self._step_count += 1
        if action.startswith("edit"): self._action_edit(action)
        test_output = self._run_tests()  隔离子进程 + 超时
        passed = "passed" in test_output and "failed" not in test_output
        reward = 1.0 if passed else 0.0  ③ 基于执行的奖励
        terminated = passed or action.startswith("submit")
        truncated = self._step_count >= self.MAX_STEPS  ④ 步数上限
        return StepResult(self._build_observation(action, test_output),
                          reward, terminated, truncated)
①②reset/step 契约为何关键
遵循 Gymnasium 标准 API 的环境可直接接入 RL 训练框架;seed 化 reset 让任意轨迹精确重放,重建隔离工作目录,检查点可支持树搜索式探索。
③reward 与 done 的语义
奖励来自实际运行测试套件而非 LLM 裁判,二元 0/1 抗 reward hacking;terminated=任务解决,truncated=预算截断——两种结束必须分开。
④步数上限防拖垮
MAX_STEPS=20 是 Episode 硬上限;每次测试在带 30s 超时的独立子进程运行,Agent 陷入死循环也不会拖垮外层训练循环。
+并行采集数据(21.5.4)
RL 训练需数百万次环境交互:进程级并行、异步 rollout worker 重叠推理延迟、向量化环境批处理 step;云上用 Ray/SLURM 分发,回放缓冲聚合轨迹。
