SFT 最佳实践PACKING · CHAT TEMPLATE · MASKING · MIXING

SFT 是 RLHF 的地基:RL 只能放大已有行为,无法引入 SFT 中完全不存在的能力——打包、掩码与数据混合决定这条上限。

85-95%序列打包效率(padding 仅 20-50%)
2-4×长方差数据集的打包加速比
T≈2多任务温度混合 · 对小数据集过采样
1-3指令微调 Epoch 已足够,过训降多样性
01序列打包 Sequence Packing
pad 到最长序列浪费 50-80% 计算;多条样本拼成 max_seq_length 单序列,块对角 mask 防跨样本污染。
02Chat 模板 · 补全掩码
推理用错模板性能显著下降;completion-only masking 把非 assistant token 的 loss 置零——多轮须 mask 所有非 assistant 轮次。
03遗忘 vs 对齐税
遗忘=权重被覆盖:回放 5-10% 预训练数据、LoRA、学习率 1-5×10⁻⁶;对齐税=知识被 KL 抑制:调 β∈[0.05,0.3]。
图 10.1 · 序列打包与补全掩码:多条样本拼进一个 max_seq_length 序列,块对角 mask 禁止跨样本 attention,loss 只落在 assistant 段
SFT 质量决定 RL 上限SFT 解对 10% 的题,RL 可推至 80%;解对率 0% 则 reward 全零、优势全零、无梯度。RL 前先测 pass@k:pass@1<5% 大概率失败。
