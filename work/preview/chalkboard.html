DPO 训练步:两条序列一个 lossPOLICY / REF · IMPLICIT REWARD · LOGSIGMOID

书 6.5.7 的 PyTorch 风格伪代码:policy 对 chosen/rejected 各算一次序列对数概率,ref 在 no_grad 下给基线,β 缩放差值进 logsigmoid——DPO 的全部数学就这几行。

def dpo_loss(model, ref_model, batch, beta=0.1):
    # ① batch:chosen/rejected 两条序列,prompt 掩为 -100
    logps_chosen   = get_sequence_logprob(model, batch["chosen"])
    logps_rejected = get_sequence_logprob(model, batch["rejected"])
    with torch.no_grad():                ② 参考模型:预计算或在此计算
        ref_logps_chosen   = get_sequence_logprob(ref_model, batch["chosen"])
        ref_logps_rejected = get_sequence_logprob(ref_model, batch["rejected"])
    chosen_rewards   = beta * (logps_chosen - ref_logps_chosen)      ③ β 乘在 logp 差上
    rejected_rewards = beta * (logps_rejected - ref_logps_rejected)
    loss = -F.logsigmoid(chosen_rewards - rejected_rewards).mean()
    return loss

def get_sequence_logprob(model, sequences):
    """仅在回答 token 上求和的对数概率。"""
    outputs = model(sequences["input_ids"], attention_mask=sequences["mask"])
    logits = outputs.logits[:, :-1, :]   ④ 为 next-token 预测做位移
    labels = sequences["labels"][:, 1:]  # 位移后的标签
    log_probs = F.log_softmax(logits, dim=-1)
    token_logps = log_probs.gather(-1, labels.unsqueeze(-1)).squeeze(-1)
    mask = (labels != -100).float()      ⑤ 只对回答 token 求和
    return (token_logps * mask).sum(dim=-1)  # 形状:[batch_size]
①两条序列同批一次前向
prompt 与回答拼成 [x; yw]、[x; yl] 两条序列,同批一次前向同时得到两个 logp——省一半调度。
②ref 冻结:预计算后驱逐
πref 全程静态:开训前整库前向一次缓存参考 logp,训练中将其驱逐出显存——70B 省约 140GB。
③β 的位置与取值

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B-Instruct", torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2")

    num_generations=8, temperature=1.0,   ① G=8 · 高温保组内多样
    max_completion_length=2048, beta=0.04, ③ KL 惩罚系数
    learning_rate=1e-6,
    per_device_train_batch_size=2,        ② 每设备 2 prompt ×8 = 16 响应
    use_vllm=True)                        ④ 8 倍生成,速度至关重要

def reward_fn(completions, prompts, **kwargs):  ⑤ Python 函数即 reward
    """返回 float 列表:正确为 1.0,错误为 0.0。"""
    rewards = []
    for completion, prompt in zip(completions, prompts):
        answer, expected = extract_answer(completion), get_ground_truth(prompt)
        rewards.append(1.0 if answer == expected else 0.0)
    return rewards

trainer = GRPOTrainer(model=model, args=grpo_config,
    reward_funcs=[reward_fn, format_reward_fn],  ⑤ 可组合多个,多目标
    train_dataset=math_dataset, tokenizer=tokenizer)

def agent_loop(goal: str, max_steps: int = 50,
               budget: TokenBudget = None):
    """The canonical agent loop structure."""
    state = initialize_state(goal)     ① 加载外部状态和目标
    for step in range(max_steps):
        thought = model.reason(state)  ② 推理(ReAct 风格)
        action = model.choose_action(state)
        observation = environment.execute(action)
        state = update_state(state, thought, action, observation)
        if state.token_count > CONTEXT_BUDGET * 0.8:
            state = compact(state)      汇总旧步骤
        if verifier.passes(state, goal): ③ 确定性检查
            persist_state(state, status="success")
            return Success(state)
        if no_progress_detected(state, window=3):  ④ 无进展
            persist_state(state, status="stuck")
            return escalate_to_human(state)
        if budget and budget.exhausted():
            persist_state(state, status="budget_exceeded")
            return escalate_to_human(state)
    persist_state(state, status="max_steps")   ⑤ 硬性上限
    return escalate_to_human(state)
①外部状态为何放循环外
LLM 在两次调用间是无状态的,循环连续性必须驻留磁盘——Markdown 进度文件、数据库或 git 日志;开局加载、每个出口回写,即进度·失败记忆·审计轨迹。
②一次迭代的执行流

④⑤终止条件:上限与无进展

用 FastMCP 写一个 MCP ServerDECLARATIVE TOOLS · AUTO SCHEMA · AUTO TRANSPORT

书 22.7.1 的完整记笔记 server:装饰器声明 tool 与 resource,Schema 与传输全自动——这就是「N×M 集成问题」的标准答案长什么样。

from pathlib import Path
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("notes-server")          ① 一个实例=一个 server
NOTES_DIR = Path.home() / ".notes"

@mcp.tool()                               ② 声明式 tool
def create_note(title: str, content: str,
                tags: list[str] | None = None) -> str:
    """Create a new text note. Use this when
    the user wants to save information."""  ③ docstring 给 LLM 看
    safe = "".join(c if c.isalnum() or c in "-_" else "_"
                   for c in title).strip()  ④ 输入校验:防路径穿越
    p = NOTES_DIR / f"{safe}.md"
    p.write_text(f"---\ntitle: {title}\n---\n\n" + content,
                 encoding="utf-8")
    return f"Note saved to {p}"
@mcp.resource("notes://{title}")        ⑤ URI 路由的只读数据
def get_note(title: str) -> str:
    return (NOTES_DIR / f"{title}.md").read_text("utf-8")

if __name__ == "__main__":
    mcp.run()  ⑥ stdio / Streamable HTTP 自动选择
①②声明式,免手写 Schema
@mcp.tool() 从 Python 类型注解 + docstring 自动推断 JSON Schema——相比低层 API 省掉整个 inputSchema 手写环节。
③docstring 是 prompt 的一部分
模型靠它决定「何时调用」。写清「何时用」比写清「怎么做」更重要——这是工具描述工程的最小单元。
④⑤校验在 server,数据与动作分离
路径穿越是 tool 的头号注入面,文件名清洗是底线;resource 是只读「数据」,tool 是带副作用的「动作」。
⑥传输对上层透明
本地子进程走 stdio,远程走 Streamable HTTP——同一份代码两种部署,Client 不需要改动。
运行pip install "mcp[cli]" · 启动:mcp run notes_server.py(stdio)或 --transport streamable-http;预期:server 就绪等待 Client 握手。

书 26.9:研究 Agent 的推理/检索/审阅被编译成图——节点是函数、State 是唯一载体、条件边画出自批评回路,checkpoint 负责可恢复。

class ResearchState(TypedDict):
    messages: Annotated[List[BaseMessage], add_messages]  ① 节点间只传 State
    error_count: int
    tool_call_count: int
    status: Literal["researching", "done", "failed"]
def route_after_llm(state: ResearchState) -> str:          ② 条件边路由
    if state["error_count"] >= 5 or state["tool_call_count"] >= 15:
        return "fail"                                预算熔断
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return "research"   无工具调用 → LLM 继续推理
async def build_graph(db_url: str) -> CompiledStateGraph:  ③ 图即控制流
    checkpointer = AsyncPostgresSaver.from_conn_string(db_url)  ④ 检查点
    builder = StateGraph(ResearchState)
    ...  # add_node ×4;START→research;tools→check;fail→END(略)
    builder.add_conditional_edges("research", route_after_llm,
        {"tools": "tools", "research": "research", "fail": "fail"})
    builder.add_conditional_edges("check",
        lambda s: "end" if s["status"] == "done" else "research",
        {"end": END, "research": "research"})   审阅未过 → 打回重做
    return builder.compile(checkpointer=checkpointer)

节点返回 dict,由图合并进 State 再传下一节点;messages 挂 add_messages reducer,追加不覆盖。完整 State 另有 topic / sources_* / report_id。

有 tool_calls 去 tools,否则回 research 继续想;错误经 AIMessage 回灌给 LLM 调整策略;error≥5 或 tool_call≥15 熔断——预算上限写进图里。
③图即控制流

④checkpoint 可恢复
AsyncPostgresSaver 每步落库,进程崩溃后从任意检查点续跑;长任务的断点续传全靠它——这是生产级与研究原型的分水岭。
