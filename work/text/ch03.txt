前言
为什么要写这本指南
在 2026 年构建智能 AI 系统，需要掌握极其广阔的知识——从 Transformer 在内部如何处理语言，
到使训练成为可能的硬件与系统，再到让训练高效的优化技术、教会模型推理并与人类意图对齐的
强化学习算法，乃至大规模协调自主系统的多智能体架构。
这些知识散落在数百篇论文、博客文章、 GitHub 仓库，以及少数实验室内部的“部落知识”之
中。本指南之所以存在，是因为 从业者需要一份覆盖整套技术栈的统一参考 ——不仅是理论，更是
让事情真正跑起来的实现细节。
我个人走向智能体 AI 的旅程
我对智能体（ agent）的迷恋始于二十年前，那时我还在攻读信息系统工程的本科学位。我选修了
面向智能体的软件工程（Agent-Oriented Software Engineering, AOSE ） [382] 课程，并学习如何用
JADE [ 22]（Java Agent DEvelopment Framework ）构建多智能体系统——这是一个遵循 FIPA [93]
标准的平台， 智能体之间通过结构化协议通信、 就共享资源协商， 并自主协作。 与此同时，Berners-Lee、
Hendler 与 Lassila 发表的奠基性论文《 The Semantic Web 》 [24] 描绘了一种机器可读知识的愿
景，让智能体能够在其上推理。这两条线索——自主智能体架构与语义知识表示——种下了一颗
种子，此后一直引导着我的职业生涯。一个早期项目让这一愿景具体化：在我未来尊敬的学术导
师 Prof. A vigdor Gal 的指导下，我们尝试用 OntoBuilder [ 103] 构建一个购物智能体——一个能够
在不同异构网站上自动填写商品搜索查询与订单的系统，通过本体匹配与映射来理解它们各异的
schema。Semantic Web 承诺，在一个结构化、机器可读的世界里，这类智能体将大放异彩。然而在
实践中，手工本体的脆弱性、真实商品数据的混乱，以及缺乏稳健的自然语言理解，让这个愿景永
远停留在“还有五年” 。
在随后的岁月里，我亲历了 AI 进步的每一次浪潮：用于组合优化的神经网络与启发式搜索；深
度学习与表征学习；大规模信息检索与个性化；以及最近的大语言模型革命。每一波浪潮都带来强
大的新工具，但梦想始终未变：构建能在复杂环境中自主理解、推理与行动的系统。
2024–2026 年之所以非凡，是因为这些线索终于汇合在一起。LLM 提供语言理解与生成能力；强
化学习教会它们推理并与人类意图对齐；工具使用协议（Model Context Protocol, MCP ）赋予它们
在世界中行动的“手” ；智能体编排框架提供了二十年前JADE 曾设想过的协作层——只是现在由
基础模型驱动，而非手工编写的本体。在很多意义上，本指南正是我希望自己在那段旅程的每一步
都能拥有的参考。
2026 年的全景
通向今天智能体 AI 系统的旅程，横跨三十年间在架构、训练与部署上不断累积的突破：
1. 架构基础（ 2017–2020）：Transformer [357] 把 self-attention 引入为一种通用的序列处理原
语。Scaling Laws 揭示：用更多数据训练的更大模型会稳定地变好。 GPT-2 与 GPT-3 证明，
仅 decoder 结构的 Transformer 在足够规模化之后，会成为有能力的 few-shot learner 。
2. 系统与效率 （2020–2023）：FlashAttention [65] 通过消除显存瓶颈让训练加速 2–4×。LoRA [147]
让在单个节点上微调 70B+ 模型成为可能。 专家混合 （Mixture-of-Experts, MoE ） 将模型容量
与算力成本解耦。vLLM 这类推理引擎把吞吐量带到了实时应用可触及的范围。

3. 基于 RL 的对齐（2022–2024）：RLHF [ 280] 把“有能力但不实用”的 base 模型变成了真
正有用的助手——这正是 ChatGPT 背后的配方。DPO [ 302] 把 reward 模型与 RL 循环压缩
成单一的监督 loss，降低了对齐的门槛。变体随之涌现： KTO [ 87]、IPO [ 14]、ORPO [ 141]、
GRPO [ 323]。
4. 推理与自主（2024–2026）：DeepSeek-R1 [ 72] 与 OpenAI 的 o1/o3 证明：RL 可以教会模型
推理本身——模型自发地发现思维链（Chain-of-Thought，CoT） 、 回溯与自我验证。 与此同时，
Model Context Protocol (MCP) 统一了工具访问、智能体到智能体（ Agent-to-Agent, A2A ）
使智能体间通信成为可能，生产级编排框架也走向成熟。
本指南的目标读者
本文档是为真正动手做东西的从业者而写：
• ML 工程师：需要理解 Transformer 内部机制、训练基础设施、优化方法，以及为何训练会发
散。
• 应用研究者：为其特定领域评估架构、微调策略与 RL 方法。
• Agent 开发者：构建生产系统，需要编排模式、记忆架构、工具集成（ MCP）以及多智能体
协作（A2A） 。
• 系统工程师：负责训练基础设施、GPU 集群、分布式训练与推理部署。
• 技术负责人：需要在全栈层面做出架构与资源决策。
我们假设读者熟悉神经网络与基础概率论。 不要求事先具备 LLM、RL 或系统方面的知识 ——
本指南从第一原理构建。
你将获得什么
读完本指南后，你将能够：
• 理解 LLM 内部机制——注意力机制、位置编码、MoE 路由、FlashAttention，以及架构选择
为何会影响下游能力。
• 对系统进行推理——GPU 显存预算、分布式训练策略（FSDP、张量/流水线并行） 、推理优化，
以及用 vLLM 进行生产部署。
• 高效训练与微调——LoRA/QLoRA、量化、知识蒸馏、优化器选择以及学习率调度。
• 将模型与人类偏好对齐 ——实现 RLHF/DPO/GRPO/KTO 流水线、调试 reward hacking 与
mode collapse ，并在 20+ 种方法中选出合适的算法。
• 构建推理模型——理解 DeepSeek-R1、o1/o3 与 QwQ 如何在没有显式示范的情况下， 通过RL
发现思维链。
• 构建智能体系统的架构 ——选择编排模式、设计记忆、通过 MCP 集成工具、通过 A2A 协调
智能体，并以生产级基准进行评估。
• 严谨地做评估——对模型质量与智能体能力应用合适的指标、基准与 LLM-as-Judge 模式。

本指南的组织方式
本指南共 30 章，按六个部分组织：
1. 第一部分 —— 基础 （第 1–3 章）：LLM 架构与优化（ Transformer、attention、位置编码、
FlashAttention、LoRA、MoE） 、系统基础（GPU 层级、分布式训练、vLLM） ，以及经典RL
理论（MDP、policy gradient 、actor-critic） 。
2. 第二部分——面向 LLM 的 RL 方法（第 4–12 章） ： 完整的 “面向LLM 的 RL” 工具箱。 先介
绍语言模型的 RL 基础，再完整地数学化处理 PPO、DPO、GRPO 与偏好优化变体（Online
DPO、KTO、IPO、ORPO、SimPO） 、reward 模型训练、SFT 最佳实践、大规模系统架构，
以及基于轨迹级 RL 的智能体训练。
3. 第三部分——推理（第 13 章） ： 大型推理模型——DeepSeek-R1、OpenAI o1/o3/o4-mini 、QwQ
——RL 如何发现思维链、MCTS、过程奖励模型（Process Reward Model, PRM ）与测试时算
力扩展（Test-Time Scaling） 。
4. 第四部分——评估（第 14 章） ：全面的LLM 评估方法论——指标、LLM-as-Judge、人工标注、
基准套件、污染检测，以及智能体评估。
5. 第五部分——智能体 AI（第 15–27 章） ：完整的智能体技术栈——智能体AI 简介、检索增强
生成（Retrieval-Augmented Generation, RAG ）与检索、记忆系统、编排与上下文管理、循环
工程（Loop Engineering ） 、设计模式、智能体环境与基准、Model Context Protocol (MCP) 、
Agent Skills 、Agent-to-Agent (A2A) 通信、多智能体系统、开发框架以及智能体 UI。
6. 第六部分——自测与参考（第 28–30 章） ：覆盖全部主题的108 道详细测验题与完整解答；一
章快速参考，整合关键公式、API 参考与失败模式诊断；以及关于未来方向的总结。
本指南包含 100+ 道详细测验题及覆盖所有主题的完整解答，并附带一章整合关键公式、API 参
考与失败模式诊断的快速参考。
设计哲学
三条原则贯穿本文档：
1. 先直觉、后形式化。每一个方程之前，都会先用通俗语言解释它的含义与重要性。
2. 面向实现。不知道如何让理论跑起来，理论就毫无用处。我们贯穿始终地提供代码、超参表、
显存预算、架构图与调试策略。
3. 对 “什么有效” 诚实相告。 我们会明确指出哪些方法经过生产验证， 哪些仍处于研究探索阶段。
范围与有意省略
本指南聚焦于文本输入、文本输出的语言模型 ，以及围绕它们构建的 RL、系统与智能体基础设施。
有几个重要领域被有意排除：
• 多模态模型（视觉–语言、音频、视频） 。多模态架构引入了独特的训练流水线（对比预训练、
跨模态对齐、模态专用编码器） 、数据精选挑战与评估协议，每一项都值得用一本书的篇幅来
讨论。将其纳入只会让范围翻倍，却无法加深贯穿本指南的 RL 与智能体核心。
• 特定领域部署（医疗、 法律、 金融、 科学发现） 。 领域适配带来监管约束、 专门评估与数据访问
问题，这些都与本文呈现的通用方法正交。我们覆盖的算法与架构正是从业者向这些领域适配
时所使用的构建模块，但适配细节交由专门的参考文献会更合适。
• 个性化与推荐系统。个性化依赖用户建模、协同过滤与交互历史架构，构成了一条平行的研究
传统。 尽管LLM 越来越多地被用在推荐系统中， 但其核心技术（序列模型、 基于bandit 的探
索、冷启动处理）足够独特，值得另行讨论。
